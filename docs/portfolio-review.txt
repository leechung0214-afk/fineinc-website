회사 홈페이지 실적 추가 검토 도구

실행 위치: D:\FINE_통합개발\06_회사홈페이지
필요 환경: Python 3.10 이상, Pillow
권장 Python: C:\Users\rcman\AppData\Local\Programs\Python\Python313\python.exe

이 도구는 현재 공개된 실적을 검증하고, 새 실적의 비공개 검토 사본과 배포 준비 묶음을 만듭니다.
운영 저장소 적용, Git commit/push, 업로드, 실제 공개는 수행하지 않습니다.
기존 공개 프로젝트의 교체·수정은 지원하지 않습니다. 신규 ID만 추가할 수 있습니다.
원드라이브 및 입력 사진 원본에는 쓰지 않습니다. 원본 이동·삭제도 하지 않습니다.

1. 현재 공개 JSON과 모든 사진 검증

python scripts/portfolio_review.py validate

--report로 비공개 보고서 경로를 지정할 수 있습니다.
기본 보고서: _개발준비/portfolio-review/reports/validate-날짜-고유번호.json
검증 성공 종료코드는 0, 검증 오류·보호정책 위반은 2입니다.
사본 검증 시 전역 --site-root에 사본의 site 폴더를 지정합니다.

python scripts/portfolio_review.py --site-root "비공개사본/site" validate

검사 범위:
- 공개 JSON의 허용키·필수키·타입, 중복 JSON 키와 프로젝트 ID
- replaceExisting은 프런트엔드와 동일하게 true만 허용
- 문자열 상한: 제목300/분야100/수행범위1000/장소500/사진설명400, JS와 같은 UTF-16 단위
- 실제 달력 날짜·시작/종료 순서·연도/월만 확인된 정밀도·미래 일자
- cover와 gallery의 모든 사진 설명 및 모든 JSON 문자열
- 금액·전화·메일·절대/내부/외부 경로·확인필요 문구의 공개 데이터 포함
- 모든 참조 사진의 존재·실제 디코딩·상대경로·링크 경계 이탈·중복
- 사진 경로의 빈 세그먼트(//)와 현재/상위 폴더(./, ../) 표기 거부
- 사진 EXIF/GPS/XMP/문자열 메타데이터 및 다중 프레임

사진 픽셀 속 글자는 OCR로 검사하지 않습니다. 계약서·영수증·금액·연락처,
공개 적합성, 사진 사용권 등은 공개승인 단계에서 사람이 원본을 직접 확인해야 합니다.
이미지 안의 글자나 인물 공개 가능성을 도구가 자동 승인하지 않습니다.

2. 기본 미승인 초안과 정제 사진 만들기

python scripts/portfolio_review.py draft --id new-show-2026 --title "행사명" --year 2026 --category "공연" --role "음향 운영" --photo "원본사진.jpg" --alt "행사 무대와 객석"

일자 확인: --start-date YYYY-MM-DD [--end-date YYYY-MM-DD]
월까지만 확인: --year YYYY --month M
연도만 확인: --year YYYY
일자와 --year/--month를 혼용하지 않습니다. 확인되지 않은 일자를 만들지 마세요.
사진은 --photo를 반복하여 여러 장 가져오며 --alt도 같은 수만큼 반복합니다.
사진/내용 입력을 생략한 초안은 확인필요 상태이며 미리보기·준비 검증에서 차단됩니다.

기본 작업 폴더: _개발준비/portfolio-review/ID-날짜-고유번호/
- draft.json: 공개 후보 항목, 기존 공개 JSON 해시
- review.json: 수행범위/사용권/공개승인, 모두 false 기본값
- imports.json: 원본 경로·원본 및 정제 사본 해시. 비공개 보관용
- assets/projects/: 방향 보정 후 EXIF/GPS/XMP/ICC 등 메타데이터를 제거한 JPEG 사본

원본의 전후 SHA-256이 같아야 가져오기를 완료합니다.
정제 사본은 긴 변 최대 1800px JPEG입니다. 원본 사진은 변경하지 않습니다.
읽기 실패 시 비공개 출력에 일부 사본이 남을 수 있으나 운영 파일에는 적용하지 않습니다.

3. 비공개 미리보기 사본 준비

python scripts/portfolio_review.py preview --draft "작업폴더/draft.json"

현재 공개 사이트 사본에 신규 후보만 추가합니다. 아직 미승인 상태여도 구조와 사진 검증을
통과하면 비공개 미리보기를 준비할 수 있습니다. 도구가 서버를 실행하거나 브라우저를 열지 않습니다.
site/를 HTTP 서버로 제공해서 확인하세요. file:// 직접 열기는 JSON을 읽지 못할 수 있습니다.

python -m http.server 8765 --bind 127.0.0.1 --directory "미리보기폴더/site"

4. 검토 후 배포 준비 묶음 만들기

review.json에서 실제 근거를 확인한 후 다음 3개를 true로 바꾸고 각각의 근거를 작성합니다.
- scopeConfirmed / scopeEvidence: 실제 수행범위
- rightsConfirmed / rightsEvidence: 사진 사용권
- publicationApproved / publicationEvidence: 사진·문구·개인정보 포함 공개승인

python scripts/portfolio_review.py prepare --draft "작업폴더/draft.json"

다른 승인 파일은 --approval로 명시할 수 있으나 ID와 subjectSha256가 일치해야 합니다.
세 항목이 정확히 true이고 근거가 채워져야 합니다. "true" 문자열, 빈 근거, 확인필요·미정은 차단합니다.
초안이나 정제 사진을 수정하면 이전 승인은 재사용할 수 없습니다.
공개 JSON 원본이 바뀐 경우에도 최신 원본으로 다시 검토해야 합니다.
초안 수정 후에는 preview를 다시 준비하고 그 결과의 review-template.json을 새 승인 명세서로
사용하세요. 새 명세서도 세 항목은 모두 false입니다. 검토 후 근거와 승인을 다시 작성하고,
prepare의 --approval에 해당 명세서를 지정하면 됩니다.

결과:
- site/: 검증된 공개 사이트 후보 사본
- deployment-site.zip: site/ 내용만 포함하는 배포 준비 파일
- validation.json, manifest.json, approval-summary.json: 비공개 검토 기록

원본 경로·imports.json·review.json·draft.json은 공개 사이트 사본과 ZIP에 넣지 않습니다.
공개 JSON·사진·정적 자산의 파일 및 조상 폴더에 symlink/junction이 있으면 차단합니다.
정적 자산의 실제 경로는 assets 안에 있어야 하며 hardlink(링크 수 2 이상) 파일도 차단합니다.
링크를 통해 비공개 작업 파일이 사이트 사본이나 ZIP에 들어가지 않도록 검사합니다.
준비 완료는 배포 완료가 아닙니다. 실제 반영·업로드는 별도 작업입니다.

출력 경로 보호

기본 출력은 _개발준비 또는 tests/_artifacts 아래입니다.
--output으로 별도 새 외부 폴더를 명시할 수 있지만 공개 저장소/입력 원본과 겹치면 거부합니다.
공개 assets, index.html, 입력 사진 폴더, 저장소를 포함하는 상위 경로, 링크/junction 출력은 거부합니다.
기존 출력 파일·폴더는 덮어쓰지 않습니다. 재실행은 새 경로를 사용하세요.
